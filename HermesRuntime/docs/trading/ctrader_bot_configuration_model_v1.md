# cTrader Bot Configuration Model V1

## Purpose

This document defines the configuration model for a later Hermes cTrader bot.

It is specification only.
It does not define cBot code.
It does not use the cTrader Order API.
It does not allow trading operations.
It does not permit demo or live execution.

## Configuration Sources

### A. Release Bundle Configuration

Generated by HermesRuntime:

- `bot_version`
- `strategy_package_version`
- `supported_assets`
- `supported_timeframes`
- `included_setups`
- `risk_profile`
- `safety_flags`
- `forbidden_capabilities`
- `schema_version`
- `release_mode`

### B. Local cBot Parameters

Set locally by the operator in cTrader:

- `release_bundle_inbox_path`
- `active_release_bundle_path`
- `last_valid_release_bundle_path`
- `local_runtime_logs_path`
- `reload_interval_seconds`
- `import_enabled`
- `manual_kill_switch`
- `max_spread_override_enabled`
- `local_spread_limit_multiplier`
- `session_filter_override_enabled`
- `log_verbosity`

### C. Runtime-Derived Values

Determined by the bot at runtime:

- `current_symbol`
- `current_timeframe`
- `bid`
- `ask`
- `spread`
- `server_time`
- `local_time`
- `market_session_status`
- `broker_symbol_mapping`
- `tick_size`
- `pip_size`

## Authority Rules

- The release bundle is authoritative for strategy, safety, and release status.
- cTrader parameters may only set local operating behavior.
- Local parameters must never relax safety flags.
- Local overrides may only become more restrictive, never riskier.
- Runtime-derived values must never overwrite bundle truth.

## Required Parameters for cBot V1

The minimum required local parameters are:

- `release_bundle_inbox_path`
- `active_release_bundle_path`
- `last_valid_release_bundle_path`
- `local_runtime_logs_path`
- `reload_interval_seconds`
- `import_enabled`
- `manual_kill_switch`
- `log_verbosity`

## Recommended Defaults

Suggested defaults:

- `reload_interval_seconds = 30`
- `import_enabled = true`
- `manual_kill_switch = false`
- `log_verbosity = normal`
- `max_spread_override_enabled = false`
- `session_filter_override_enabled = false`

## Parameter Validation

A configuration is invalid if any of the following is true:

- a required path is empty
- `reload_interval_seconds < 5`
- `reload_interval_seconds > 3600`
- `log_verbosity` is unknown
- `import_enabled = false` and no `last_valid_release_bundle` exists
- `manual_kill_switch = true`
- a local override would relax safety

## Override Rules

### Allowed

- make the spread limit stricter
- make the session filter stricter
- increase logging
- disable import if `last_valid_release_bundle` exists

### Not Allowed

- disable `no_auto_trading`
- enable `broker_orders_enabled`
- enable `live_trading_enabled`
- enable `order_api_enabled`
- disable `paper_mode`
- reduce `forbidden_capabilities`
- increase risk limits without a new release bundle

## Safety Behavior

If configuration validation fails:

- set `bot_config_invalid`
- set `kill_switch_active=true`
- keep `broker_action=none`
- produce no paper decision
- write a log entry

## Mapping to cTrader Parameters

Later cBot parameters should appear in the cTrader UI as standard bot inputs.

V1 defines the parameter contract, but does not implement the bot or the UI wiring.

## Safety Invariants

These values remain mandatory:

- `no_auto_trading=true`
- `human_review_required=true`
- `broker_orders_enabled=false`
- `live_trading_enabled=false`
- `order_api_enabled=false`
- `paper_mode=true`
- `broker_action=none`

## Open Implementation Questions

- Should the local parameter set be stored as a cTrader profile or a bot preset?
- Should `local_spread_limit_multiplier` be capped globally or by bundle?
- How should `manual_kill_switch` be surfaced in the later UI?
- Should import disabling be temporary or sticky until a valid bundle arrives?
- Which parameters should be editable at runtime versus only at bot start?

## Summary

V1 separates configuration into release bundle truth, local operator parameters, and runtime-derived market values.

Safety stays bundle-driven, local overrides may only tighten controls, and invalid configuration always triggers a kill switch.
